1. CORE ORGANISING PRINCIPLE
--------------------------------------------------------------------------------

Report BY HYPOTHESIS / COMPARISON, not by run. Every main-text table and figure
exists to answer one contrast from the causal chain (hypotheses in STUDY_REPORT
Section 2; causal comparison map in Section 1.2 below):

    R0 -> R1   H1  does the SSL objective help on identical data?
    R1 -> R2   H2  does full-distribution exposure add beyond the objective?
    R2 -> R3   H3  does broad head/threshold fine-tuning unlock FA reduction?
    R4 vs R0   H4  is any gain merely broader fine-tuning, no SSL?
    R3 vs R4   H5  HEADLINE: SSL vs no-SSL, both broad fine-tuning
    Frozen vs Full (all SSL runs)  H6  representation vs initialisation?

Rule: any number that does not serve a contrast goes to SUPPLEMENTARY. This
single rule collapses the full grid into a small main-text set.

This matrix guarantees, at a glance, that every hypothesis has (i) a home in a
main-text artifact and (ii) a significance test behind its claim. No hypothesis
is orphaned; no claimed difference is asserted without a test.

2. EVALUATION FRAMEWORK (THREE LAYERS) -- WHAT IS MEASURED
--------------------------------------------------------------------------------

All evaluation is performed on the held-out validation/test partitions of the
FULL, un-downsampled stream. Layer 1 uses the baseline eval_utils.py unchanged
for direct comparability with M3. (Moved here from STUDY_REPORT Section 8;
STUDY_REPORT now points to this section.)

2.1 Layer 1 -- Standard performance metrics (eval_utils.py)

  This layer reproduces the FULL baseline metric set (eval_utils.py) unchanged,
  so every number is directly comparable to M3. Exact metric keys below.

  Segment level : accuracy, precision, recall (= sensitivity), specificity,
                  Youden's J, macro-F1 (f1_macro), MCC, AUROC, AUPRC, and the
                  segment false-alarm rate
                  (far_per_hour_seg_CORRECTED_2_5s_denom). Confusion counts
                  tp/fp/fn/tn are retained.
  Event level   : per-mouse chronological predictions are post-processed by a
                  FIXED, ORDERED four-stage pipeline, then matched to ground
                  truth by any-overlap. Reported metrics (baseline
                  evaluate_event_level, full set):
                    - raw counts: n_predicted_events, tp, fp, fn;
                    - precision, recall (= sensitivity), F1;
                    - false alarms per hour (far_per_hour_event_CORRECTED);
                    - false alarms per 24 h (= FAR/hr x 24), reported for
                      cross-study comparability (Table 4);
                    - mean detection latency (mean_detection_latency_sec).
                  BOTH aggregate AND per-subject (per-mouse) versions are
                  produced; the per-subject values feed the subject-level
                  statistics in Section 5. Raw fp counts are retained (not only
                  the derived FAR/hr), since reviewers expect the count behind
                  the rate.

                  Post-processing order (applied in this exact sequence):
                    1. Probability smoothing        (moving window = 3 segments)
                    2. Minimum-event filtering       (drop events < min-event; see
                                                      MIN-EVENT SWEEP below)
                    3. Refractory-period merging     (merge events < 30 s apart)
                    4. Maximum-duration filtering    (drop events > 120 s)
                  The decision rule P > 0.5 is applied to the smoothed
                  probabilities (after stage 1) to form candidate events.

                  MIN-EVENT SWEEP AND OPERATING-POINT SELECTION -- FOLLOWS
                  DL_WITH_SSL_GA EXACTLY (reuse/adapt postproc_sweep.py, extended
                  across this study's runs x protocols; no new machinery). Event
                  metrics are computed OFFLINE on cached predictions at min-event
                  durations of 10, 15, 20, 25, and 30 s; the post-processing
                  order is fixed to the baseline's adopted min_then_refractory.
                  The operating point is SELECTED ON VALIDATION from the
                  Recall-vs-FAR/hr Pareto / impact plots -- the point in the
                  BOTTOM-RIGHT ideal region (high sensitivity, low FAR/hr) --
                  exactly as the baseline selected its 25 s [TBD-7]; then applied
                  on test. The same script emits, per variant, the comparison CSV
                  and the BASELINE 2 x 3 IMPACT FIGURE -- rows: val (top) / test
                  (bottom); columns: (1) Event Precision/Recall/F1 vs min-event,
                  (2) Event-level FAR/hr vs min-event, (3) Recall-vs-FAR/hr Pareto
                  (bottom-right = ideal, points labelled by duration). Because the
                  order is fixed to min_then_refractory, each panel shows a SINGLE
                  series (not the baseline's two-order overlay). Main text shows
                  this figure for the headline variant(s) (Fig 2); per-variant
                  figures for all runs x protocols go to supplementary.
                  (Provenance / script: Section 6.)

2.2 Layer 2 -- Artefact-proxy stratified false-alarm number

Because artefacts are unlabeled, a label-free proxy identifies non-ictal
segments that are almost certainly artefacts AND morphologically resemble
seizures (the segments most likely to trigger false alarms).

  Stratum A ("seizure-mimicking non-ictal"). Non-ictal (label 0) segments that
  are BOTH:
    * far from any seizure: min distance to nearest seizure > 60 s (candidate
      margin 120 s), using the baseline min_distance_to_seizure() logic; AND
    * morphologically seizure-like, per a MULTI-FEATURE morphology score rather
      than a single amplitude threshold. Candidate features (single-channel-
      valid): line length (high-frequency / muscle activity), kurtosis (spiky /
      electrode-pop transients), signal envelope amplitude (movement), variance
      / power, and a high-band power ratio (EMG band). Features are standardised
      across the non-ictal pool; segments whose morphology lies within the
      seizure feature manifold (near the seizure feature-centroid / high
      composite score) are selected.

  A single high-amplitude or high-variance threshold is deliberately NOT used,
  as it misses muscle/electrode artefacts that are not the largest-amplitude
  events.

  Stratum B (control). Far-from-seizure, LOW-morphology quiet background. If
  false alarms fall on A but not on B, the improvement is specific to hard
  artefacts rather than a global threshold shift.

  Metric. For each trained model: segment-level false-alarm rate on A, and,
  after the standard post-processing, false-alarm events per artefact-hour on
  A; reported alongside B. This is the primary metric for H2, H3, and the H5
  headline (Table 2).

  Guardrails.
    * The stratum is defined ONLY from signal statistics and seizure distance,
      never from any model's predictions (no circularity).
    * All thresholds/percentiles are fixed on validation before test.
    * A random sample (~50-100 segments) of stratum A is visually audited to
      confirm the segments are genuine non-seizure artefacts; the audit is
      documented in supplementary (Section 7).

2.3 Layer 3 -- Representation (embedding) analysis

Purpose: show WHY false alarms fall -- that the SSL encoder separates
artefacts from seizures in feature space where the baseline overlaps them.

  * Extract frozen-encoder pooled embeddings (num_filters-dim) for a balanced
    held-out sample across groups: seizure, artefact-proxy (A), quiet
    background (B), and optionally peri-ictal near-seizure.
  * Encoders compared: ALL runs -- R0 (baseline M3, loaded from DL_WITH_SSL_GA),
    R1, R2, R3, and R4. Including R1 is essential: because R1 applies the SSL
    objective on the artefact-poor D0 while R2 applies it on the full
    distribution, the R0 -> R1 -> R2 progression visually distinguishes whether
    artefact/seizure separation arises from the OBJECTIVE (H1) or from
    full-distribution DATA EXPOSURE (H2). R3/R4 complete the broad-fine-tune
    contrast.
  * Encoder state analysed: for SSL runs (R1-R3) the frozen encoder as used
    under the linear-probe protocol (the representation as learned by SSL); for
    R0/R4, which have no SSL stage, their trained supervised encoder. This
    asymmetry is unavoidable (R0/R4 have no encoder to freeze) and is stated
    explicitly in the write-up.
  * Qualitative: UMAP (primary) and t-SNE (secondary) 2-D projections coloured
    by group (Figure 3).
  * Quantitative (computed in the FULL embedding space, not the 2-D
    projection, to avoid reliance on a single figure; Table 3):
      - seizure-vs-artefact linear-probe AUROC (logistic probe on frozen
        embeddings): higher => better separation;
      - silhouette score and/or Fisher ratio between the seizure and artefact
        clusters.

5. STATISTICAL REPORTING
--------------------------------------------------------------------------------

  * SINGLE SEED (42), as in the baseline, for full reproducibility. Statistical
    variance for every claim comes from the SUBJECT population -- the per-subject
    paired tests below resample MICE, which answers "is the difference real?"
    without repeating seeds. A single seed is therefore statistically defensible.
    (Model-INITIALISATION variance -- "did one lucky init win?" -- is a separate,
    secondary question; if a reviewer challenges it, a small seed sweep on the
    headline pair R3/R4 can be added as a targeted rebuttal, not built now.)
  * Every CLAIMED contrast (H1-H6) is backed by a significance test -- not just
    a selected few. Test choice follows the metric type:
      - AUROC differences            -> DeLong test;
      - rates (FAR/hr, sensitivity)  -> paired bootstrap 95% CI on the
                                        difference (report whether the CI
                                        excludes zero);
      - paired binary segment preds  -> McNemar test;
      - protocol comparison (H6)     -> Wilcoxon signed-rank across subjects.
    Per-contrast assignment (matches the Section 1.1 matrix):
      H1 R0->R1 : DeLong (AUROC) + McNemar (segment preds)
      H2 R1->R2 : paired bootstrap (artefact FA on A) + DeLong (probe AUROC)
      H3 R2->R3 : paired bootstrap (artefact FA and event FAR/hr)
      H4 R4 vs R0: DeLong (AUROC) + paired bootstrap (artefact FA)
      H5 R3 vs R4: paired bootstrap (artefact FA and event FAR/hr)  [HEADLINE]
      H6 frozen vs full: Wilcoxon signed-rank on the two quantities in 5.1
  * Multiple-comparison control. Because several contrasts are tested, p-values
    are corrected across the H1-H6 family (Holm-Bonferroni) and both raw and
    corrected values are reported.
  * Aggregate event metrics PER SUBJECT (report subject-level means) to avoid
    pseudoreplication: mice contribute 1-178 seizures each, so pooling segments
    would bias toward high-burden animals. All paired tests use subject as the
    pairing unit.
  * All headline numbers come from the TEST partition (validation is the
    development set; see STUDY_REPORT Sections 5.4 and 6.1).
  * Operating point for EVENT-level tests. Event-level significance tests are
    run at each model's validation-selected best min-event (the primary
    operating point; criterion in Section 2.1), AND repeated at the common 25 s
    baseline point. A headline claim (e.g. H5, R3 vs R4) is reported as robust
    only if it holds at BOTH points. The full sweep (Fig 2) stays descriptive;
    significance is not tested at all five durations (that would multiply the
    comparisons and muddy the Holm-Bonferroni correction).

5.1 The two H6 quantities (representation vs initialisation)

  H6 claims SSL improves the learned REPRESENTATION, not merely the training
  starting point. Two numbers decide it (see Figure 4):
    Q1  Frozen advantage: does the FROZEN SSL model (encoder locked, linear
        head only) already outperform R0 on artefact FA and AUROC? A positive,
        significant Q1 means the features themselves carry the benefit.
    Q2  Gap closure: is the FROZEN-minus-FULL performance gap SMALLER for the
        SSL runs than for a supervised reference? A shrinking gap means the
        representation -- not fine-tuning -- supplies most of the gain.
  Both are reported with subject-level Wilcoxon signed-rank tests and CIs.

6. HOW THE BASELINE MIN-EVENT SWEEP WORKED (CONFIRMED) AND WHAT WE ADOPT
--------------------------------------------------------------------------------

Confirmed from DL_WITH_SSL_GA/postproc_sweep.py and eval_utils.py:

  * OFFLINE and decoupled from training. The sweep reads cached prediction
    NPZs (y_true, y_prob, plus per-segment chronology: mouse_id, chrono_idx,
    t_start_sec). No model forward pass, CPU-only. One inference pass per model
    is cached; post-processing is then swept cheaply.
  * Grid = post-processing ORDER {refractory_then_min, min_then_refractory}
    x MIN_EVENT_SEC {10, 15, 20, 25, 30} = 10 configurations per partition.
  * Run independently on val and test (train optional, sibling output root).
  * Held fixed during the sweep: smoothing window W = 3, threshold tau = 0.5,
    refractory period = 30 s, max-event = 120 s, FAR/hr denominator
    step_sec = 2.5 s.
  * Per-config outputs via eval_utils.write_event_level_bundle; a comparison
    CSV (20 rows for val+test); and a 3-panel impact figure:
      (1) event Precision / Recall / F1 vs MIN_EVENT_SEC;
      (2) event FAR/hr vs MIN_EVENT_SEC;
      (3) Recall vs FAR/hr Pareto scatter, points annotated with the second
          value (bottom-right = ideal).
  * The two orderings were compared as a methodological ablation; the baseline
    adopted min_then_refractory (clinical-standard; cited Saab 2020, Tang 2022,
    Persyst, Encevis) and selected 25 s.

What THIS project adopts and changes:

  * ADOPT the offline cached-prediction sweep pattern (one forward pass ->
    cache y_prob + chronology -> sweep post-processing offline) for every run
    and both protocols. This makes the 5-run x 2-protocol x 5-sec surface cheap
    to produce.
  * ADOPT the Recall-vs-FAR/hr Pareto figure as main-text Figure 2.
  * FIX the post-processing order to the canonical smoothing -> min-event ->
    refractory -> max-duration sequence (= min_then_refractory). We do NOT
    sweep the order (the baseline's order ablation is settled); we sweep ONLY
    MIN_EVENT_SEC {10,15,20,25,30}.
  * SELECT the min-event OPERATING POINT on validation, per model, from the
    Recall-vs-FAR/hr Pareto / impact plots -- the point in the BOTTOM-RIGHT
    ideal region (high sensitivity, low FAR/hr) -- EXACTLY as the baseline
    selected its 25 s, by REUSING postproc_sweep.py rather than adding new
    machinery [TBD-7]; apply it on test. The decision THRESHOLD remains fixed at
    P > 0.5 (not tuned). The full sweep (all durations incl. 25 s) is reported
    as the Pareto curve / impact figure. Selection is on VALIDATION, never test.

  Extended across THIS project's structure:
    * "variant" = RUN (R0-R4) x PROTOCOL (frozen / full): one top-level output

9. STATISTICS PRIMER (PLAIN-LANGUAGE APPENDIX TO SECTION 5)
--------------------------------------------------------------------------------

Plain-language companion to Section 5, for readers new to statistics. It does
not change the plan; it explains WHY each test is used and HOW the headline
claim is produced.

9.1 The one question every test answers

  When R3 (SSL) shows fewer false alarms than R4 (no SSL), the worry is: did R3
  really do better, or did it just get lucky on this particular set of mice?
  Every test below answers exactly that -- "is this difference real, or could
  it be chance?"

9.2 Two ways to express the answer

  * p-value: the probability of seeing a difference this large BY LUCK ALONE if
    the two models were truly equal. Small p (conventionally < 0.05) means luck
    is an unlikely explanation, so the difference is probably real.
  * Confidence interval (CI): a plausible range for the true difference, e.g.
    "1.8 fewer false alarms/hour, 95% CI [0.9, 2.7]". If the range does NOT
    include zero, the difference is statistically real. CIs are preferred
    because they also show HOW BIG the effect is, not just whether it exists.

9.3 The key setup: "paired, per mouse"

  Every metric is computed PER MOUSE, then the two models are compared mouse by
  mouse.
  * Why per mouse: mice differ hugely (1-178 seizures each). Pooling all
    segments lets a few seizure-heavy mice dominate (pseudoreplication).
  * Why paired: for each mouse we take model-A-score minus model-B-score.
    Comparing on the SAME mouse cancels out "this mouse is just easy/hard"
    (like testing the same students under two teaching methods).
  So the raw material for most tests is a LIST OF PER-MOUSE DIFFERENCES (one
  number per mouse).

9.4 Which tool for which kind of number

  * Paired bootstrap -- for RATES (false alarms/hour, sensitivity).
    "Bootstrap" = with, say, 20 mice, draw a new fake sample of 20 mice WITH
    REPLACEMENT (some appear twice, some not at all) and recompute the average
    difference; repeat ~10,000 times. The middle 95% of those answers IS the
    confidence interval. Intuitively: "reshuffle the mice many times and see
    how much the answer wobbles." Makes no bell-curve assumption -> robust for
    messy rate metrics.
  * DeLong test -- for AUROC (how well the model ranks seizures above
    non-seizures). AUROC needs a purpose-built comparison test; DeLong is the
    standard, expected one, so reviewers accept it without question.
  * McNemar test -- for YES/NO predictions on the SAME segments. It looks only
    at segments where the two models DISAGREE: how many did A get right that B
    got wrong, vs the reverse. A lopsided result means one model is genuinely
    better. Agreements are ignored (they say nothing about which is better).
  * Wilcoxon signed-rank -- for FROZEN vs FULL (H6). Compares the per-mouse
    differences without assuming a bell curve: it ranks the differences by size
    and checks whether they lean mostly positive or negative. The
    assumption-light cousin of the paired t-test.

9.5 Multiple-comparison correction (Holm-Bonferroni)

  We test ~6 hypotheses. If you run many tests, something will look
  "significant" by pure chance (test 20 things at p<0.05 and ~1 fires randomly).
  Holm-Bonferroni tightens the significance bar according to how many tests were
  run, so a surviving result is trustworthy. Both RAW and CORRECTED p-values are
  reported.

9.6 Why a SINGLE seed here (and where the variance comes from)

  The previous project used one seed (42) for reproducibility; this project keeps
  that. The statistical variance behind every claim comes from the SUBJECT
  population -- the per-subject paired tests resample MICE, so "is the difference
  real?" is answered WITHOUT repeating seeds. Running many seeds would
  additionally characterise model-INITIALISATION variance (did one lucky init
  win?) -- a separate, secondary question, handled only if challenged, via a
  small seed sweep on the headline pair. Single seed 42 keeps the study fully
  reproducible and matched to the baseline.

9.7 Worked example -- the headline claim (R3 vs R4, false alarms)

  1. Compute false-alarm rate per mouse for R3 and R4 (single seed 42).
  2. Per mouse, take R3 - R4.
  3. Bootstrap those differences -> mean reduction + 95% CI.
  4. Check the CI excludes zero; report the p-value.
  5. Apply Holm-Bonferroni across all hypotheses.
  6. State it: "SSL reduced false alarms by X/hour (95% CI [a, b], p = ...,
     Holm-corrected)."
  That sentence is the defensible claim.
